# ЭТАП 5: Сбор контактов, регистрация на воркшоп и Upsell

## САММАРИ

**Цель:** Реализовать сбор лидов (телефон — обязательно + Telegram username — автоматически), регистрацию на воркшоп и универсальный механизм показа Upsell. Это ключевая точка монетизации — из квеста/арены/дожима конвертируем в воркшоп → upsell.

**Что делаем:**
- `handlers/contacts.py` — сбор телефона (обязательно) + авто-захват Telegram @username
- `utils/validation.py` — ValidationResult dataclass, validate_phone (validate_email сохранён, но не используется в контактах)
- Регистрация на воркшоп (workshop_registered = TRUE в PostgreSQL)
- `handlers/upsell.py` — ЕДИНАЯ функция show_upsell_if_available()
- Показ upsell при ЛЮБОМ workshop_registered = TRUE (из квеста, арены, дожима)

**Что ИЗМЕНЕНО vs старая версия ТЗ:**
- ❌ Email **удалён** из потока сбора контактов — не нужен
- ❌ Кнопка "Пропустить телефон" **удалена** — телефон обязателен
- ❌ Кнопка "Пропустить email" **удалена** — email не собираем
- ✅ Telegram @username **захватывается автоматически** из `message.from_user.username`
- ✅ Телефон — **обязательный шаг**, пропустить нельзя
- ✅ FSM упрощён: waiting_phone → confirming (2 состояния вместо 3)
- ✅ Кнопки подтверждения: "Подтвердить", "Изменить телефон" (без "Изменить email")

**Что ОБЯЗАТЕЛЬНО сохраняем:**
- FSM-состояния: waiting_phone → confirming
- Валидация: +7, +375, 8XXX (Россия/Беларусь)
- Кнопки: "Оставить контакт", "Пропустить" (пропуск всего блока контактов), "Подтвердить", "Изменить телефон"
- Тексты: запрос телефона, формат, ошибки валидации, успех
- Уведомление админам при новом контакте (включает @username)

**Ключевые бизнес-правила:**
1. Контакты собираются ПОСЛЕ квеста/арены, перед финальным экраном
2. Контакты НИКОГДА не удаляются при сбросе прогресса
3. Upsell показывается СРАЗУ после workshop_registered = TRUE
4. Upsell НЕ зависит от точки входа (квест, арена, дожим)
5. Если мест нет — upsell не показывается, переход к FINAL
6. Telegram @username сохраняется автоматически при каждом касании (уже есть в users.username)
7. Телефон — обязательное поле, без него нельзя подтвердить контакт

**Ключевые изменения vs текущий код:**
- Контакты хранятся в таблице users (не в отдельной таблице contacts)
- После подтверждения контактов → регистрация на воркшоп → upsell (а не просто promo)
- ValidationResult — единый класс (уже реализован)
- workshop_registered — флаг в PostgreSQL (уже есть в schema.sql)
- Email убран из потока (колонка email остаётся в БД для обратной совместимости, но не заполняется)

```
       │

       │
       ▼ Авто-захват: Telegram @username из message.from_user.username
       │
       ▼ Ввод телефона (FSM: waiting_phone) ← ОБЯЗАТЕЛЬНЫЙ ШАГ
       │   Валидация: +7, +375, 8XXX → нормализация
       │   Кнопки "Пропустить" НЕТ!
       │
       ▼ Подтверждение (FSM: confirming)
       │   "📞 Телефон: +7... 🔗 Telegram: @username"
       │   [✅ Подтвердить] [✏️ Изменить телефон]
       │
       ▼ Сохранение в БД → уведомление админам
       │
       ▼ Воркшоп → upsell
```

### FSM-состояния (упрощено)
```
ContactStates:
  waiting_phone  — ожидание ввода телефона (обязательно)
  confirming     — подтверждение данных (телефон + username)
```

### Кнопки
| Кнопка | Когда показывается | callback_data |
|--------|-------------------|---------------|
| 📱 Оставить контакт | Начало сбора | `contact:start` |
| ⏭️ Пропустить | Начало сбора (пропуск всего блока) | `contact:skip_all` |
| ✅ Подтвердить | Экран подтверждения | `contact:confirm` |
| ✏️ Изменить телефон | Экран подтверждения | `contact:edit_phone` |

### Авто-захват Telegram @username
```python
username = callback.from_user.username  # Может быть None
await state.update_data(
    tg_username=f"@{username}" if username else None,
    phone=None,
)
```
Username сохраняется в `users.username` — колонка уже есть в schema.sql.

## 4. HANDLERS/UPSELL.PY — ЕДИНАЯ ТОЧКА ВХОДА

### Зачем отдельный модуль
Upsell показывается из 3+ мест:
1. После квеста → контакты → воркшоп → **upsell**
2. После арены → контакты → воркшоп → **upsell**
3. После миниквеста дожима → воркшоп → **upsell**

Если дублировать логику — race conditions и несогласованность. Одна функция:

```python
# handlers/upsell.py

async def show_upsell_if_available(bot, user_id, pool, redis_conn):
    """
    ЕДИНАЯ функция показа upsell.
    Вызывается из ЛЮБОЙ точки, где workshop_registered становится TRUE.
    
    Логика:
    1. Проверить, не показывали ли уже (upsell_shown)
    2. Подсчитать доступные места (paid + held < 10)
    3. Если есть → HOLD слот → показать оффер
    4. Если нет → пропустить → FINAL
    """
```

### Поток upsell
```
show_upsell_if_available()
  │
  ├─ upsell_shown = TRUE → пропуск (уже показывали)
  │
  ├─ remaining_slots > 0:
  │     HOLD слот в Redis (атомарный Lua, 15 мин)
  │     Показать оффер:
  │       "🔥 ЭКСКЛЮЗИВНОЕ ПРЕДЛОЖЕНИЕ
  │        Разбор бизнеса: {price} ₽
  │        Осталось мест: {remaining}/10
  │        Бронь: 15 минут"
  │       [💳 Оплатить] [❌ Пропустить]
  │     upsell_shown = TRUE
  │
  └─ remaining_slots = 0:
        Пропуск → FINAL
```

## 5. СОХРАНЕНИЕ КОНТАКТОВ В POSTGRESQL

### Что сохраняется
| Поле | Откуда | Обязательно |
|------|--------|-------------|
| `users.phone` | Ввод пользователя + валидация | ✅ ДА |
| `users.username` | Авто: `message.from_user.username` | ✅ (авто, может быть NULL если у юзера нет @username) |
| `users.first_name` | Авто: `message.from_user.first_name` | ✅ (авто) |

### SQL для сохранения контактов
```sql
UPDATE users 
SET phone = $2, updated_at = NOW()
WHERE user_id = $1
```

`username` и `first_name` уже обновляются при каждом взаимодействии через middleware / start handler.

### Правило: контакты НИКОГДА не удаляются
При `/reset_user` (админ):
```sql
UPDATE users SET
    quest_state = 'start', quest_completed = FALSE, ...
    -- phone, username, workshop_registered НЕ трогаем!
WHERE user_id = $1
```

## 7. УЛУЧШЕНИЯ ЭТОГО ЭТАПА

### 7.1 Технологические
- **ValidationResult dataclass** — единый контракт валидации
- **Единая функция upsell** — нет дублирования, нет race conditions
- **workshop_registered в PostgreSQL** — персистентный флаг, не теряется при перезапуске
- **Упрощённый FSM** — 2 состояния вместо 3 (убран waiting_email)

### 7.2 Функциональные
- **Обязательность телефона** — кнопки "Пропустить телефон" нет
- **Авто-захват @username** — пользователю не нужно вводить ник вручную
- **Пропуск всего блока** — если пользователь не хочет оставлять контакты, он пропускает весь блок
- **Контакты из арены** — та же логика, что и из квеста (единый start_contact_collection)
- **Повторный запрос** — если контакты уже есть, предлагаем обновить (не блокируем)

### 7.3 Для вовлечённости
- **Контекстный CTA** — после квеста: "Получи разбор своего бизнеса с ИИ!" (привязка к квесту)
- **Социальное доказательство** — "Уже {count} человек записались на воркшоп!"
- **Ограничение мест** — "Осталось {remaining}/10 мест" (создаёт FOMO)
- **Таймер 15 минут** — "Бронь действует 15 минут" (срочность)
- **Бесшовный переход** — контакты → воркшоп → upsell — пользователь не чувствует "продажу"
